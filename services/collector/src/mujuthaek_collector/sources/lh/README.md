# LH 수집기

LH 공고를 **팀 공통 파이프라인**(`pipeline.py`) 위에서 수집해요. 원본 저장(collector DB·S3), 버전 비교, 새벽 정정 확인, `raw.notice.collected` 이벤트 발행은 공통 파이프라인이 하고, 이 폴더는 **LH 공고를 어떻게 읽나**만 맡아요.

```bash
# 저장소 루트에서 make infra && make migrate-collector 후 (services/collector)
LH_API_KEY=공공데이터포털_인증키 uv run python -m mujuthaek_collector run-once lh
LH_API_KEY=… uv run python -m mujuthaek_collector run-once lh --recheck   # 마감 전 공고 다시 열어 정정 확인
uv run pytest tests/sources/lh                                         # LH 테스트 (실제 사이트에 요청하지 않아요)
```
인증키는 공공데이터포털에서 4개 API를 모두 활용신청한 키예요: LH 분양임대공고문 조회(15058530)·상세정보(15057999)·공급정보(15056765), 마이홈 공공주택 모집공고(15108420). 키가 없으면 LH만 BLOCKED로 멈추고 다른 출처는 그대로 돌아요.

## 게시판 두 개
| 게시판 | 목록 | 왜 |
| --- | --- | --- |
| `open` | LH 분양임대공고문 API의 마감 전 공고 (게시일 3년 전~오늘, 마감일 오늘 이후) | 주 목록 |
| `myhome` | 마이홈 모집공고 API(임대·분양) 중 공급기관이 LH인 줄 | LH가 '접수마감'으로 바꿔 `open`에 없는 상시모집·선착순 공고를 잡아요 (2026-10-15: 11건) |

- 글 키는 **LH 공고 ID(`PAN_ID`)**예요. 두 게시판에 다 있는 공고도 한 번만 저장돼요 (역할 분담 4-04 "LH 공고 하나당 원본 하나").
- 목록은 한 번에 전부 1페이지로 돌려줘요. LH는 마감일이 바뀌면 게시일이 오래된 공고도 목록에 다시 들어와서, 1페이지만 보고 끝내면 놓쳐요.
- 목록은 **오래된 공고부터** 돌려줘요. 파이프라인이 목록 순서대로 등록하면서 정정공고의 원래 공고를 찾기 때문이에요. LH API 순서(최신 먼저) 그대로면 정정공고가 원래 공고보다 먼저 등록돼서 연결되지 않아요(2026-10-16 실측: 17건 중 0건 연결).
- 마이홈 목록의 다른 기관 공고(경북개발공사 등)는 쓰지 않아요. 지방 공사 공고는 각 게시판 수집기가 맡아요.

## 글 하나 (`LhSource.fetch_detail`)
1. **LH 목록 줄 찾기**: `myhome`에서만 보이는 공고는 상세 API에 필요한 다섯 값을 얻으려고 LH 목록에서 다시 찾아요 (마이홈 공고일 하루치 → 단지명 같은 공고명 단어). 못 찾으면 그 글만 FAILED로 두고 다음 회차에 다시 찾아요(3번까지).
2. **상세정보 API + 공급정보 API + 같은 공고의 마이홈 줄**을 합쳐 원본 하나로 만들어요.
3. **본문 글자**(`detail.py`): 일정·단지·접수처·기타사항·신청자격·첨부 이름·공급정보·마이홈 줄을 응답의 한글 칸 이름으로 써요. 부를 때마다 바뀌는 응답 시각(`resHeader`)·요청 값(`dsSch`)·첨부 다운로드 주소는 넣지 않아서, 내용이 같으면 새벽 정정 확인에서 새 버전이 생기지 않아요.
4. **첨부**(`documents.py`): 첨부 종류 칸으로 공고문(정정본 우선, PDF 우선)과 주택목록 엑셀을 골라 파이프라인에 넘겨요. 붙임·배치표·가격표는 받지 않고 원본에 이름·주소만 남겨요.
5. **호별 표**: 공급정보 표를 팀 공통 칸(주택형·전용면적·공급 호수·보증금·월임대료)으로 바꿔요. 금액이 '공고문 참조'면 비워요. 주택목록 엑셀과 공고문 표는 파이프라인이 공통 표 읽기로 읽어요.
6. **시군구 코드**: 마이홈 필지번호(`pnu`) 앞 5자리 (LH API에는 시군구 코드가 없어요).
7. **원본 보관**: 목록 줄·찾은 응답·상세·공급정보 응답·마이홈 줄·받지 않은 부속 첨부를 항목 `_raw`에 그대로 넣어요 (`raw_post_versions.meta`). `_`로 시작하는 항목은 AI 추출 글자에 들어가지 않아요.

## 분류 (`classify.py`)
공고 유형 칸(`UPP_AIS_TP_NM`·`AIS_TP_CD_NM`)으로 나눠요. 공통 분류기(제목 규칙)는 LH의 '…선착순 일반매각 공고'를 제외로, '(순번추첨 동호지정)'이 든 모집공고를 후속 안내로 봐서 쓰지 않아요.

| LH | 파이프라인 종류 | 상세를 여나 |
| --- | --- | --- |
| 모집공고 | NOTICE | 열어요 |
| 정정공고 | CORRECTION (원래 공고는 공통 규칙으로 제목 비교) | 열어요 |
| 취소공고 | EXCLUDED | 안 열어요 (이벤트 계약에 취소 종류가 없어요. 팀 합의 필요) |
| 토지·상가·매입 신청·보상 등 | EXCLUDED | 안 열어요 |

## robots.txt 예외 (`client.py`)
`apply.lh.or.kr/robots.txt`는 `User-agent: *`에 `Disallow: /lhapply/lhFile.do`예요. 팀 결정(2026-10-14)으로 **상세 API가 알려주는 첨부 주소에 한해** 받아요 (주택목록 엑셀은 2026-10-15 추가, 팀 승인 필요 — ADR-021 초안). 공통 요청 클라이언트(`PoliteClient`)를 그대로 쓰고, `config.ROBOTS_OVERRIDES`의 경로 하나만 예외로 두며 쓸 때마다 로그를 남겨요. 공공데이터포털 API는 0.5초 간격(공통 기본은 4초)으로 불러요.

## 아직 정하지 않은 것 (팀 합의)
- 취소공고를 이벤트로 어떻게 보낼지 (지금은 EXCLUDED)
- 상가(사업공간): 계약이 `HOUSING`만 받아서 `config.INCLUDE_BUSINESS = False`
- 공고문이 둘인 공고(대구연호 A-2·A-3 블록 등)는 공통 규칙상 첫 공고문 하나만 받아요
- 분양가: 이벤트 계약에 칸이 없어서 호별 표의 `raw`에만 있어요
