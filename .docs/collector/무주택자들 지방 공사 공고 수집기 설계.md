# 무주택자들 지방 공사 공고 수집기 설계

Oct 15, 2026 · @beomjunkwon

## 1. 이 문서로 만드는 것

지방 공사 9곳의 **주거 공고 게시판**에서 새 모집공고를 자동으로 모으는 **collector 워커**(파이썬 3.12)를 처음부터 만들어요.

collector가 하는 일은 이 다섯 가지예요.

1. 기관 게시판에서 새 글을 찾아요. robots.txt를 지키고 요청 사이에 4초를 둬요.
2. 제목으로 모집공고·정정공고·후속 안내·제외할 글을 나눠요.
3. 모집공고의 상세 화면과 공고문 원본(PDF·HWP·HWPX) 하나, 주택목록(엑셀 우선)을 받아요.
4. 공고문에서 글자와 표를 뽑고, 표에서 호별 임대조건(전용면적·보증금·월임대료 등)을 읽어요.
5. 원본이 바뀌었을 때만 새 버전으로 저장하고, `raw.notice.collected` 이벤트를 RabbitMQ로 보내요. 자격 조건 해석은 다음 단계(extraction 워커)가 해요.

수집 방식은 **HTTP 요청 + BeautifulSoup** (HTML 읽기)이에요. 9곳 모두 브라우저 없이 목록·상세·첨부를 받을 수 있는 걸 확인했어요.

**이 문서의 범위가 아닌 것**: 상가·사업공간 공고, LH·청약홈·마이홈 API, 정책·창업지원 API. 이 출처들도 같은 공통 코드(요청 클라이언트, 저장, 이벤트)를 쓰지만 수집기는 각 담당이 만들어요.

## 2. 따르는 팀 결정

| 항목 | 결정 |
| --- | --- |
| 수집 방식 | 기관 게시판은 HTTP 요청 + 파서로 받아요. 9곳 모두 브라우저 없이 목록·상세·첨부를 받을 수 있어요 |
| 실행 | collector는 파이썬 3.12 워커예요. EC2 1대에 api·extraction과 함께 Docker 컨테이너로 떠요. collector 컨테이너는 CPU 1개·메모리 1GB 상한, 죽으면 자동 재시작 |
| 저장 | RDS PostgreSQL 1대 안의 collector 전용 데이터베이스에 저장해요. 다른 프로그램(api, extraction)은 이 데이터베이스에 접속하지 않아요. 원본은 고치지 않고 버전으로 쌓아요 |
| 원본 파일 | S3(로컬은 MinIO)에 둬요. 기관 다운로드 주소·해시·추출 글자·호별 표는 계속 보관하고, 파일 자체는 마감 후 6개월(예비입주자 모집은 1년)이 지나면 삭제해요 |
| 전달 | 저장과 같은 트랜잭션에서 아웃박스 테이블에 이벤트를 적고, 발행기가 5초마다 RabbitMQ로 `raw.notice.collected`를 보내요. 형식은 `contracts/events/raw.notice.collected.v1.json` |
| AI | collector는 AI를 쓰지 않아요. 표는 규칙으로 읽고, 조건·일정의 의미 해석은 extraction 워커가 해요 |
| 개인정보 | 당첨자·예비자·대상자 명단 파일은 받지 않고 미리보기도 열지 않아요 |
| 예의 | robots.txt를 표준(RFC 9309)대로 지키고, 같은 도메인은 4초 간격, 403·429·대기실 화면이면 그 회차를 멈춰요. 출처는 하나씩 순서대로 돌려요 |

**지금 단계**: 이번 주는 로컬(Docker의 PostgreSQL·RabbitMQ·MinIO)에서 개발하고 확인해요. RDS·S3·EC2 연결은 다음 주에 해요. 코드는 환경 변수가 없으면 로컬 값을 쓰도록 만들어서, AWS로 옮길 때 코드는 고치지 않고 환경 변수만 바꿔요.

## 4. 전체 흐름

```
스케줄러 (평일 9~18시 매시 5분 + 매일 새벽 3시 정정 확인, 출처는 하나씩 순서대로)
 │
 └─ 출처마다 (pipeline.run_source)
     ├─ 수집 회차 시작                crawl_runs에 RUNNING
     └─ 게시판마다
         ├─ 목록 1~5페이지            1페이지 해시가 지난번과 같고 밀린 글이 없으면 → 끝
         │   └─ 글마다
         │       ├─ 이미 본 글         목록의 상태·마감일만 갱신
         │       ├─ 365일 넘은 글      SKIPPED로 기록 (열지 않음)
         │       └─ 새 글 분류         NOTICE·CORRECTION → 열기 / FOLLOW_UP → 원래 공고가 있을 때만 / 나머지 → SKIPPED
         ├─ 밀린 글(PENDING·FAILED) + 새 글, 한 번에 최대 20건 (나머지는 PENDING으로 다음 회차)
         │   └─ 글마다
         │       ├─ 상세 화면 읽기     본문, 항목, 첨부 목록
         │       ├─ 공고문 1개         PDF 우선, 못 읽으면 HWP·HWPX → 글자·표 추출
         │       ├─ 주택목록 최대 2개  엑셀 우선 → 호별 임대조건
         │       ├─ S3에 원본 저장
         │       └─ 한 트랜잭션        버전 비교 → 새 버전 저장 + 아웃박스에 raw.notice.collected
         └─ 밀린 글이 없으면 목록 해시 저장
     └─ 회차 마무리                   crawl_runs에 SUCCESS / BLOCKED / FAILED, 새 글 수, 경고

아웃박스 발행기 (5초마다) ──▶ RabbitMQ (mujuthaek.events, 라우팅 키 raw.notice.collected) ──▶ extraction
```

**글 상태 (`raw_posts.status`)**

| 상태 | 뜻 | 다음 회차 |
| --- | --- | --- |
| `SKIPPED` | 열지 않기로 한 글 (모집공고가 아님, 원래 공고가 없는 후속 안내, 365일 넘음) | 다시 보지 않음 |
| `PENDING` | 열어야 하는데 이번 회차 한도(20건)를 넘었거나, 차단으로 멈춘 글 | 목록 위치와 상관없이 먼저 처리 |
| `FAILED` | 상세 화면 구조가 달라 못 읽은 글 | 3번까지 다시 시도 |
| `DONE` | 저장 완료 | 새벽 정정 확인 때 바뀌었으면 새 버전 |

**오류에 따른 반응**

| 오류 | 언제 | 반응 |
| --- | --- | --- |
| `BlockedError` | robots.txt 금지, 403·429, 대기실 화면, robots.txt 서버 오류 | 그 출처의 이번 회차를 멈춤 (`BLOCKED`). 처리 중이던 글은 `PENDING` |
| `ParseError` | 목록 표·본문 영역을 못 찾음 (사이트 구조 변경 신호) | 그 글만 `FAILED`, 경고 기록. 목록이면 그 게시판을 멈춤 |
| `FileRejected` | 첨부가 robots.txt 금지 경로로 넘겨짐, 30MB 초과, 파일 대신 웹페이지 | 그 파일만 건너뛰고 경고 |
| 연결 오류·5xx | 일시적인 오류 | 2번까지 다시 시도, 그래도 안 되면 그 글 `FAILED` |

### 수집기와 추출 서버가 나누는 일

**기관 사이트에 요청하는 건 collector 한 곳뿐이에요.** extraction(AI 추출)은 기관 사이트에도, 보통은 S3에도 요청하지 않고 RabbitMQ로 받은 이벤트만 보고 일해요.

```
기관 사이트 (SH, GH …)
   │  ① 목록·상세·첨부 요청 (robots.txt, 같은 도메인 4초 간격)
   ▼
collector
   ├─ ② 원본 파일 → S3 (로컬은 MinIO)           보관용
   ├─ ③ 글·버전·뽑은 글자·호별 표 → collector DB
   └─ ④ 이벤트 raw.notice.collected → RabbitMQ
                                          │
                                          ▼
                                     extraction
                                     ⑤ 이벤트 안의 글자·호별 표로 AI 추출
                                        (기관 사이트 요청 없음, S3는 아주 긴 공고만)
```

| 이벤트에 담기는 것 | 내용 |
| --- | --- |
| `text` | 제목·게시일·항목·본문 + 공고문 PDF·HWP에서 뽑은 글자 전체 |
| `units` | 공고문·주택목록 표에서 읽은 호별 임대조건 (주택형, 면적, 보증금, 월임대료 …) |
| `files` | 첨부 이름, 해시, 기관 다운로드 주소 (사람에게 보여줄 링크용. extraction이 이 주소로 요청하지 않아요) |
| `textKey` | 글자가 20만 자를 넘을 때만 채워지는 S3 위치. 이벤트에는 앞부분만 있고 전체는 S3의 `text/…`에서 읽어요 |

S3에 원본 파일을 두는 이유는 두 가지예요. 글자 뽑는 방법을 개선했을 때 기관에 다시 요청하지 않고 보관한 원본으로 다시 뽑을 수 있고, AI 결과가 이상할 때 그 시점의 원본을 확인할 수 있어요(기관이 파일을 내리거나 바꿔도 남음). 보관 기한(마감 후 6개월, 예비입주자 모집은 1년)이 지나면 파일만 지우고 글자·표는 DB에 남겨요.

이렇게 나눈 이유는 기관 서버 부담과 차단 위험을 collector 한 곳에서만 관리하고, AI 비용이 드는 extraction은 네트워크 오류·파일 파싱 실패와 섞이지 않게 "글자를 받아 해석"하는 일만 하게 하려는 거예요.

### 기관에 요청하는 빈도

"4초"는 확인 주기가 아니라 **한 번 수집할 때 같은 기관에 보내는 요청 사이 간격**이에요. 기관에 확인하러 가는 건 정해진 시간에만 해요.

| 언제 | 하는 일 |
| --- | --- |
| 평일 9\~18시, 매시 5분 (하루 10번) | 9곳의 게시판 14개 확인 |
| 매일 새벽 3시 | 마감 전 공고를 다시 열어 정정됐는지 확인 |

한 번 확인할 때 게시판마다 목록 1페이지만 받아보고, 지난번과 같으면 바로 끝내요. 새 글이 없으면 한 번에 요청 14번(4초 간격, 1분 남짓)으로 끝나요. 새 공고가 있는 게시판만 상세와 첨부를 더 받고, robots.txt는 기관마다 하루 한 번만 받아요.

| 상황 | 하루 요청 수 (대략) |
| --- | --- |
| 새 글 없는 평일 | 목록 14번 × 10회 = 약 140번 |
| 새 공고 1건 | + 상세 1번, 첨부 1\~3번 |
| 새벽 정정 확인 | 마감 전 공고 수만큼 상세·첨부 (게시판마다 최대 20건) |

사람이 게시판을 하루 몇 번 새로고침하는 정도라 기관 서버 부담은 작아요. 모집공고는 보통 게시 후 며칠\~몇 주 뒤 접수가 시작되고 대부분 추첨이라 실시간까지는 필요 없지만, 잔여세대 선착순 같은 공고를 놓치지 않으려고 매시로 정했어요. 실제 하루 새 공고 수를 보고 줄이려면 스케줄 한 줄(`hour="9-18"` → `hour="9,12,15,18"`)만 바꾸면 돼요.

"5초마다"는 기관 요청이 아니라 내부 작업이에요. collector DB의 아웃박스에 쌓인 이벤트를 RabbitMQ로 보내는 발행기가 5초마다 돌아요.

### 비용

확인 빈도를 바꿔도 비용은 사실상 그대로예요. 지금 로컬 단계는 전부 무료이고, AWS로 옮긴 뒤에도 마찬가지예요.

| 항목 | 확인 빈도에 따라 바뀌나 | 이유 |
| --- | --- | --- |
| 기관 사이트 요청 | 무료 | 공개 게시판이에요 |
| EC2·RDS | 안 바뀜 | 켜져 있는 동안 월 고정 금액이에요. collector는 api·extraction과 같은 서버에서 돌아요 |
| 받는 데이터 | 거의 무료 | AWS는 들어오는 트래픽에 요금을 받지 않고, 하루 수십 MB 수준이에요 |
| S3 | 빈도와 무관 | 확인할 때가 아니라 새 공고·정정이 생겼을 때만 저장해요 |
| AI 추출 (extraction) | 빈도와 무관 | 실제로 돈이 드는 곳이지만, collector는 내용이 바뀌었을 때만 이벤트를 보내서 새 공고·정정 건수로 정해져요 |

주의할 점은 상세 화면 본문에 매번 바뀌는 값(조회수, 현재 시각 등)이 섞이는 경우예요. 그러면 내용이 같아도 새 버전과 이벤트가 생겨 AI 비용이 나가요. 코드는 본문 영역 글자와 첨부 파일 해시로만 비교해서 이걸 막아뒀고, 출처마다 "`--recheck`에서 바뀌지 않은 공고는 새 버전이 생기지 않음"을 완료 기준으로 확인해요.

## 6. DB 테이블

collector 데이터베이스에 테이블 8개를 만들어요. 원본은 고치지 않고 버전으로 쌓고, 목록에서 본 글은 열지 않은 글까지 모두 남겨서 다음 회차에 다시 판단하지 않아요.

| 테이블 | 담는 것 |
| --- | --- |
| `sources` | 수집 출처 9곳 (`code`가 수집기 code와 같아야 함) |
| `source_boards` | 게시판별 목록 1페이지 해시, 목록 0건 연속 횟수 |
| `crawl_runs` | 수집 회차 기록 (시작·끝, 상태, 새 글 수, 오류·경고) |
| `raw_posts` | 목록에서 본 모든 글 (상태 `SKIPPED`·`PENDING`·`DONE`·`FAILED`, 원래 공고 연결) |
| `raw_post_versions` | 글의 버전 (본문, 항목, AI에 넘긴 전체 글자, 해시) |
| `raw_files` | 받은 첨부 (기관 주소, 해시, S3 위치, 보관 기한) |
| `raw_texts` | 첨부에서 뽑은 글자 (파일이 지워져도 남음) |
| `raw_units` | 호별 임대조건 (원래 머리글 값과 이상값 기록 포함) |
| `outbox` | 보낼 이벤트 (저장과 같은 트랜잭션) |

`migrations/V202610150900__collector_init.sql`

```sql
-- collector 데이터베이스. 모든 출처의 원본을 고치지 않고 버전으로 쌓아요.

create table sources (
    code       text primary key,          -- 수집기 code (sh, gh, bmc, ih, dcco, dudc, umca, gbdc, gndc)
    name       text not null,
    enabled    boolean not null default true,
    created_at timestamptz not null default now()
);

insert into sources (code, name) values
    ('sh', 'SH 서울주택도시공사'), ('gh', 'GH 경기주택도시공사'), ('bmc', '부산도시공사'),
    ('ih', 'iH 인천도시공사'), ('dcco', '대전도시공사'), ('dudc', '대구도시공사'),
    ('umca', '울산도시공사'), ('gbdc', '경상북도개발공사'), ('gndc', '경상남도개발공사');

-- 게시판별 상태: 목록 1페이지 해시(같으면 그 회차 바로 끝), 목록 0건 연속 횟수(구조 변경 감지)
create table source_boards (
    source_code    text not null references sources (code),
    board_key      text not null,
    last_list_hash text not null default '',
    empty_runs     int  not null default 0,
    last_run_at    timestamptz,
    primary key (source_code, board_key)
);

create table crawl_runs (
    id          uuid primary key,
    source_code text not null references sources (code),
    started_at  timestamptz not null default now(),
    finished_at timestamptz,
    status      text not null default 'RUNNING',  -- RUNNING, SUCCESS, BLOCKED, FAILED
    new_count   int  not null default 0,
    error       text                              -- 오류 또는 경고 모음
);

-- 목록에서 본 모든 글. 열지 않은 글(SKIPPED)도 남겨서 다음 회차에 다시 판단하지 않아요.
create table raw_posts (
    id             uuid primary key,
    source_code    text not null references sources (code),
    board_key      text not null,
    post_key       text not null,                 -- 출처 안에서 유일 (게시판이 여러 개면 접두어)
    kind           text not null,                 -- NOTICE, CORRECTION, FOLLOW_UP, EXCLUDED
    title          text not null,
    posted_on      date,
    detail_url     text,
    list_item      jsonb not null,                -- 목록에서 읽은 값 그대로 (PENDING 글을 다음 회차에 다시 열 때 사용)
    status         text not null,                 -- SKIPPED, PENDING, DONE, FAILED
    attempts       int  not null default 0,       -- FAILED 재시도 횟수 (3번까지)
    last_error     text,
    list_status    text,                          -- 목록의 상태 (접수중, 모집종료 …)
    deadline_on    date,
    parent_post_id uuid references raw_posts (id), -- 정정공고·후속 안내가 가리키는 원래 모집공고
    latest_version int  not null default 0,
    created_at     timestamptz not null default now(),
    updated_at     timestamptz not null default now(),
    unique (source_code, post_key)
);
create index raw_posts_queue_idx on raw_posts (source_code, board_key, status) where status in ('PENDING', 'FAILED');

create table raw_post_versions (
    id           uuid primary key,
    raw_post_id  uuid not null references raw_posts (id),
    version      int  not null,
    content_hash text not null,                   -- 본문 + 첨부 해시. 같으면 새 버전을 만들지 않음
    body_text    text not null,
    meta         jsonb not null default '{}',     -- 상세·목록의 항목 (유형, 지역, 공고상태 …)
    full_text    text not null,                   -- AI 추출에 넘긴 전체 글자 (제목·게시 정보·본문·공고문)
    crawl_run_id uuid references crawl_runs (id),
    collected_at timestamptz not null default now(),
    unique (raw_post_id, version)
);

create table raw_files (
    id           uuid primary key,
    version_id   uuid not null references raw_post_versions (id),
    idx          int  not null,
    name         text not null,
    role         text not null,                   -- NOTICE_DOC, UNIT_LIST
    download_url text not null,                   -- 기관 다운로드 주소 (계속 보관)
    file_hash    text not null,
    size_bytes   bigint not null,
    s3_key       text,                            -- 보관 기한이 지나 삭제되면 null
    stored_until date not null,                   -- 마감(없으면 게시) + 6개월, 예비입주자 모집은 1년
    text_status  text,
    deleted_at   timestamptz
);

create table raw_texts (
    id      uuid primary key,
    file_id uuid not null references raw_files (id),
    text    text not null                         -- 파일이 지워져도 추출한 글자는 계속 보관
);

create table raw_units (
    id           uuid primary key,
    version_id   uuid not null references raw_post_versions (id),
    source_file  text,                            -- 어느 파일(또는 '상세 화면')에서 읽었는지
    page         int,
    complex      text,
    district     text,
    address      text,
    unit         text,
    floor        text,
    house_type   text,
    target_group text,
    rooms        text,
    area_m2      numeric,
    deposit_won  bigint,
    rent_won     bigint,
    supply_count int,
    elevator     text,
    parking      text,
    raw          jsonb not null default '{}',     -- 원래 머리글: 값 (해석이 틀렸을 때 확인용)
    checks       jsonb not null default '[]'      -- 말이 안 돼서 비운 값
);

create table outbox (
    event_id       uuid primary key,
    event_type     text not null,
    schema_version int  not null,
    payload        jsonb not null,
    created_at     timestamptz not null default now(),
    published_at   timestamptz,
    attempts       int  not null default 0
);
create index outbox_unpublished_idx on outbox (created_at) where published_at is null;
```

## 7. 실행과 운영

### Dockerfile — `services/collector/Dockerfile`

빌드는 **저장소 루트에서** 해요(`libs/python-platform`을 같이 넣어야 해서). `uv.lock`을 커밋해두고 `--frozen`으로 설치해서, 로컬과 같은 버전이 들어가게 해요.

```dockerfile
# 빌드 컨텍스트는 저장소 루트예요: docker build -f services/collector/Dockerfile -t mujuthaek-collector .
FROM python:3.12-slim
COPY --from=ghcr.io/astral-sh/uv:0.5.11 /uv /usr/local/bin/uv
ENV UV_LINK_MODE=copy PYTHONUNBUFFERED=1 TZ=Asia/Seoul

WORKDIR /app
COPY libs/python-platform libs/python-platform
COPY services/collector services/collector
WORKDIR /app/services/collector
RUN uv sync --no-dev --frozen

# 일반 사용자로 실행
RUN useradd --create-home collector && chown -R collector /app
USER collector

EXPOSE 8091
HEALTHCHECK --interval=60s --timeout=5s --start-period=30s \
  CMD python -c "import urllib.request; urllib.request.urlopen('http://127.0.0.1:8091/health', timeout=3)"
CMD ["uv", "run", "--no-dev", "python", "-m", "mujuthaek_collector", "run"]
```

### docker compose — `infra/docker-compose.yml`의 collector 부분

팀 로컬 설정에 collector 서비스가 이미 있어요. 평소엔 `make infra`로 DB·RabbitMQ·MinIO만 띄우고 수집기는 `uv run`으로 직접 실행하고, 전체를 Docker로 띄울 때는 `make up`(`apps` 프로필)을 써요. 컨테이너 안에서는 주소가 `localhost`가 아니라 서비스 이름(`postgres`, `rabbitmq`, `minio`)이라서 환경 변수로 넘겨요.

```yaml
  collector:
    build: { context: .., dockerfile: services/collector/Dockerfile }
    profiles: [apps]
    depends_on:
      migrate-collector: { condition: service_completed_successfully }
      rabbitmq: { condition: service_healthy }
    environment: &worker-env
      SERVICE_NAME: collector
      DB_URL: postgresql://collector_app:${COLLECTOR_DB_PASSWORD}@postgres:5432/collector
      RABBITMQ_URL: amqp://${RABBITMQ_USER}:${RABBITMQ_PASSWORD}@rabbitmq:5672/
      S3_ENDPOINT: http://minio:9000
      S3_BUCKET: ${S3_BUCKET}
      AWS_ACCESS_KEY_ID: ${MINIO_ROOT_USER}
      AWS_SECRET_ACCESS_KEY: ${MINIO_ROOT_PASSWORD}
    ports: ["8091:8091"]
```

### AWS 연결 때 (다음 주 예정)

지금 로컬 개발에는 필요 없어요. AWS로 옮길 때 `infra/docker-compose.prod.yml`로 같은 collector 서비스에 재시작·메모리 상한·S3(EC2 역할 인증)·로그 전송을 더하고, 환경 값만 바꿔요. 코드는 그대로예요.

```yaml
# infra/docker-compose.prod.yml
collector:
  restart: unless-stopped
  environment:
    S3_ENDPOINT: ""          # 비우면 AWS S3. 인증은 EC2 역할로 (키를 넣지 않음)
    AWS_ACCESS_KEY_ID: ""
    AWS_SECRET_ACCESS_KEY: ""
  deploy:
    resources:
      limits: { cpus: "1", memory: 1g }
  logging:
    driver: awslogs
    options: { awslogs-group: /mujuthaek/collector, awslogs-region: ap-northeast-2 }
```

| 항목 | 로컬 (지금) | AWS (다음 주) |
| --- | --- | --- |
| `DB_URL` | 기본값 (`localhost:5432/collector`) | RDS의 collector 데이터베이스 (Parameter Store에서 주입) |
| DB 준비 | `make infra`가 데이터베이스·계정을 만들고, `migrate-collector`가 테이블을 만듦 | RDS에 `infra/db/init/01-databases.sql`을 한 번 실행하고 같은 마이그레이션 적용 |
| `RABBITMQ_URL` | 기본값 (`localhost:5672`) | EC2의 RabbitMQ 컨테이너 (`rabbitmq:5672`) |
| `S3_ENDPOINT` | 기본값 `http://localhost:9000` (MinIO) | 빈 값(`""`) → AWS S3 |
| S3 인증 | 기본값 minio / minio-pass | EC2 역할 (`s3:PutObject`, `s3:DeleteObject`를 `raw/*`, `text/*`에만). 키는 넣지 않음 |
| `COLLECTOR_DELAY_SECONDS` | `4.0` | `4.0` (낮추지 않음) |
| 로그 | 화면 | CloudWatch Logs (`/mujuthaek/collector`), 30일 보관 |

### 매일 보는 것

`status` 명령이나 `/health`로 출처별 마지막 결과를 보고, 문제가 있으면 아래 쿼리로 원인을 찾아요.

```sql
-- 최근 하루 동안 차단·실패한 회차
select source_code, started_at, status, left(error, 200)
from crawl_runs where started_at > now() - interval '1 day' and status in ('BLOCKED', 'FAILED')
order by started_at desc;

-- 목록이 계속 비는 게시판 (구조 변경 의심)
select source_code, board_key, empty_runs, last_run_at from source_boards where empty_runs >= 3;

-- 3번 다 실패해서 더 이상 시도하지 않는 글 (사람이 확인)
select source_code, post_key, title, last_error from raw_posts where status = 'FAILED' and attempts >= 3;

-- 밀려 있는 글 수
select source_code, count(*) from raw_posts where status = 'PENDING' group by source_code;

-- 아직 안 보낸 이벤트 (RabbitMQ 장애 확인)
select count(*), min(created_at) from outbox where published_at is null;
```

| 이런 게 보이면 | 할 일 |
| --- | --- |
| 같은 출처가 계속 `BLOCKED` | 간격을 늘리거나 그 출처를 잠시 멈춤(`update sources set enabled = false`). 기관에 문의가 필요하면 담당자와 상의 |
| `empty_runs >= 3` 또는 `ParseError` 경고가 이어짐 | 기관 화면이 바뀐 것. `save-fixtures`로 새 화면 저장 → 파서 고치기 → 테스트 |
| `FAILED` 3번 | `last_error`를 보고 파서 문제면 고친 뒤 `update raw_posts set attempts = 0, status = 'PENDING' where id = …`로 다시 시도 |
| 아웃박스가 쌓임 | RabbitMQ 상태 확인. 살아나면 5초 안에 알아서 다시 보내요 (`relay`로 바로 보낼 수도 있음) |

정기 수집(`run`, `run-all`)은 `sources.enabled`가 true인 출처만 돌아요. 문제가 생긴 출처는 `update sources set enabled = false where code = 'ih'`처럼 잠시 멈추고, 고친 뒤 true로 돌려요. `run-once <출처>`는 멈춘 출처도 직접 실행할 수 있어서 고친 걸 확인할 때 써요.

### 지켜야 할 것

| 항목 | 규칙 |
| --- | --- |
| 요청 예절 | robots.txt 확인, 같은 도메인 4초 간격, 출처는 하나씩. 대기실·로봇 확인 화면은 우회하지 않고 멈춤 |
| 개인정보 | 당첨자·예비자·대상자 명단 파일은 받지도 열지도 않음. 로그에 본문을 통째로 남기지 않음 |
| 원본 보관 | 원본은 고치지 않고 버전으로 쌓음. 파일은 보관 기한이 지나면 `cleanup`이 지움 |
| 비밀 값 | DB 비밀번호·S3 키는 환경 변수로만. 코드·저장 화면(fixtures)에 넣지 않음 |
