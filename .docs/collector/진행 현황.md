기준 문서
- [수집기 설계](무주택자들%20지방%20공사%20공고%20수집기%20설계.md): 결정, 흐름, DB, 운영, 완료 기준
- [수집기 전체 코드](무주택자들%20지방%20공사%20공고%20수집기%20전체%20코드.md): 9곳 코드, 테스트, Docker
- 결정 기록: [수집은 HTTP + BeautifulSoup](../adr/수집은-HTTP와-BeautifulSoup.md)

이 문서는 작업 일지예요. 단계마다 **한 것 / 왜 / 문서와 다른 점 / 확인 결과 / 남은 일**을 바로 적어요.

## 이번 목표
설계 문서의 진행 순서 1~2단계를 끝내요.
1. 공통 코드, 마이그레이션, 파이프라인, 공통 테스트를 저장소에 넣고 `uv run pytest`가 통과해야 해요.
2. 대전(`dcco`)으로 "출처 하나의 완료 기준"을 전부 확인해요.

기관 9곳의 코드는 모두 넣어요. 다만 실제 사이트로 끝까지 확인하는 건 이번에는 대전만이에요. 나머지는 설계 문서 순서대로 다음에 해요(iH, 대구 → GH·부산 → 경북·경남 → SH → 울산).

문서에 없어서 새로 만드는 것
- `libs/python-platform`(`mujuthaek_platform`): 문서 코드가 부르는 `ids`, `events`, `outbox`, `broker`, `db`, `logging`, `contracts`
- `contracts/events/raw.notice.collected.v1.json`
- 로컬 인프라
  - MinIO 대체 이미지: 원래 이미지를 받을 수 없어요.
  - `make infra`·`make up`, Flyway `migrate-collector`

## 단계별 기록

### 1. 문서 정리 (`docs/adr-move-dotdocs`)
- **한 것**
  - `docs/`를 `.docs/`로 옮겼어요. 설계 문서는 `.docs/collector/`에 있어요.
  - 설계 문서 이름 `무주택자들 수집기 Playwright 전환 설계.md`를 `무주택자들 지방 공사 공고 수집기 전체 코드.md`로 바꿨어요. 문서 제목이 "전체 코드"이고, 새 설계에서 Playwright는 쓰지 않아서예요.
  - [개발 환경](../개발%20환경.md)을 새로 썼어요: 로컬 인프라, Docker가 필요한 명령, 브랜치·PR 규칙, CI 체크, CODEOWNERS, 알려진 문제.
  - 결정 기록 두 개를 `.docs/adr/`에 남겼어요.
    - [브랜치 흐름과 CI 기준](../adr/브랜치-흐름과-CI-기준.md)
    - [수집은 HTTP + BeautifulSoup](../adr/수집은-HTTP와-BeautifulSoup.md)
  - `.gitignore`에 `.DS_Store`를 추가했어요.
- **왜**
  - 오늘 정한 레포 설정(룰셋, CI, 커버리지)이 대화와 GitHub 설정 화면에만 있었어요. 팀원이 볼 수 있는 곳에 남기려는 거예요.
  - 결정 기록 파일은 번호 없이 주제 이름으로 뒀어요. 팀 ADR 원본(artifact)에 이미 ADR-006·020 같은 번호가 있어서, 겹치지 않게 하려는 거예요.

### 2. 파이썬 공통 라이브러리와 이벤트 계약 (`feat/libs-python-platform`)
- **한 것**
  - `libs/python-platform`(`mujuthaek_platform`): `ids`, `events`, `outbox`, `broker`, `db`, `logging`, `contracts`. 함수 목록과 사용 예는 [README](../../libs/python-platform/README.md)에 있어요.
  - `contracts/events/raw.notice.collected.v1.json`: 봉투와 payload. 칸은 설계 문서 5-13의 이벤트 표를 따랐어요.
  - CI python 잡에 platform 테스트를 추가했어요. 잡 이름 `python (ruff)`는 필수 체크 이름이라 그대로 뒀어요.
  - 결정 기록: [이벤트 봉투와 아웃박스](../adr/이벤트-봉투와-아웃박스.md)
- **왜**: 설계 문서 코드가 이 함수들을 부르는데, 라이브러리 코드는 문서에 없었어요.
- **설계 문서 코드에 맞춘 것**
  - `new_event(event_type, producer, payload)`의 결과에 `eventType`과 `payload`가 있어요. `test_pipeline`이 이 두 칸을 확인해요.
  - `outbox.add(cur, event)`: `storage.save_version`이 트랜잭션 커서로 불러요.
  - `outbox.relay_once(conn, channel)`: `exchange_declare(**kwargs)`와 `basic_publish(exchange, routing_key, body, properties)`를 키워드로 불러요. `test_storage_postgres`의 가짜 Channel 모양에 맞춘 거예요.
- **문서와 다른 점**
  - 문서에 없던 걸 정했어요: 아웃박스 `payload` 칸에는 payload만이 아니라 **봉투 전체**를 넣어요. 받는 쪽이 `eventId`로 중복을 거르게 하려는 거예요.
  - 스키마의 `field`는 지금 `HOUSING`만 받아요. 상가 등이 생기면 스키마를 넓혀요.
- **확인 결과**
  - `uv run pytest` 10개 통과: uuid7 순서·버전, 봉투, relay_once, 계약 통과 1개와 거부 5개, JSON 로그
  - `ruff check`, `format --check` 통과
  - 파이썬 3.12.14로 실행했어요(`.python-version` 3.12로 고정).

### 3. 로컬 인프라 (`chore/infra-collector-local`)
- **한 것**
  - `infra/docker-compose.yml`
    - minio를 `bitnamilegacy/minio:2025.7.23`으로 바꿨어요. 버킷은 `MINIO_DEFAULT_BUCKETS=${S3_BUCKET}`으로 자동 생성해요.
    - `minio-init`을 없애고, `migrate-collector`(`flyway/flyway:11.14`, apps 프로필)를 추가했어요.
  - `infra/.env.example`: `MINIO_ROOT_USER=minio`, `MINIO_ROOT_PASSWORD=minio-pass`, `S3_BUCKET=mujuthaek-raw`로 맞췄어요(collector 기본값과 같아요). 두 번 들어가 있던 `ANTHROPIC_API_KEY`도 정리했어요.
  - 루트 `Makefile`: `make infra`, `up`, `down`, `clean`, `migrate-collector`, `ps`, `logs`, `help`
  - README·CLAUDE.md의 인프라 명령을 `make infra`로 바꿨어요.
  - 결정 기록: [로컬 MinIO 이미지](../adr/로컬-MinIO-이미지.md)
- **왜**: 설계 문서는 `make infra`, MinIO(`minio`/`minio-pass`), `migrate-collector`를 전제로 하는데 저장소에는 없었어요. 공식 MinIO 이미지는 받을 수 없어요.
- **문서와 다른 점**
  - MinIO 웹 콘솔(`http://localhost:9001`)이 없어요. 2025-07 버전부터 커뮤니티판에서 빠졌어요.
  - 그래서 설계 문서의 "받은 원본 파일 확인" 방법을 `mc ls` 명령으로 고쳤어요(설계, 전체 코드 두 문서 모두).
- **확인 결과**
  - `make infra`: postgres, rabbitmq, minio 모두 healthy
  - S3 health 200
  - 버킷은 `mc ls local/` → `mujuthaek-raw/`
  - `migrate-collector`: Flyway가 collector DB에 접속했어요. 마이그레이션 파일은 4번에서 들어와서 지금은 "No migrations found"가 나와요.

### 4. collector 공통 코드 (`feat/collector-core`)
- **한 것**
  - 전체 코드 문서의 코드 블록을 제목의 파일 경로 기준으로 꺼내 그대로 넣었어요.
    - `pyproject.toml`, `uv.lock`, `.python-version`(3.12)
    - `migrations/V202610150900__collector_init.sql`
    - `config.py`, `errors.py`
    - `core/`: robots, http_client, html, classify, files, versioning, documents/hwp·text·tables, file_store, publisher, storage
  - 테스트: `fakes.py`, `conftest.py`, `test_config`, `test_robots`, `test_classify`, `test_files`, `test_html_and_tables`, `test_http_client`, `test_contract`
  - CI python 잡에 collector 테스트를 추가했어요.
  - CLAUDE.md의 파이썬 명령 주석을 collector 기준으로 풀었어요.
- **문서와 다른 점**
  - **robots.txt 캐시를 프로세스 전체로 옮겼어요**(`core/http_client._ROBOTS_CACHE`, 키는 (User-Agent, 도메인), 24시간).
    - 설계 4장은 "robots.txt는 기관마다 하루 한 번만"이라고 해요. 그런데 문서 코드는 캐시가 `PoliteClient` 인스턴스 안에 있어요.
    - 스케줄러는 회차마다 클라이언트를 새로 만들어서, 그대로면 매시 다시 받아요(하루 약 10번).
    - 테스트: `test_robots_txt_is_fetched_once_across_clients`(클라이언트 3개 → robots.txt 1번). `conftest`에 캐시를 비우는 autouse fixture를 추가했어요.
  - 그 밖의 코드는 문서와 같아요. `ruff format`이 테스트 파일 끝 줄바꿈만 맞췄어요.
- **확인 결과**
  - `uv run pytest`: 31개 통과(문서 코드 30개 + 캐시 테스트 1개)
  - `ruff check`, `format --check` 통과. collector는 문서대로 줄 길이 160이에요.
  - `make migrate-collector` → 마이그레이션 `202610150900 - collector init` 적용, 테이블 9개, `sources` 9행
  - 환경 변수 없이 `Settings.from_env()` → `S3FileStore`로 로컬 MinIO에 `raw/dcco/43-1/v1/00-모집_공고문_최종_.pdf` 올리기, 목록, 지우기 확인
  - pyhwp 명령(`hwp5html`, `hwp5txt`)이 `.venv/bin`에 설치됐어요.

### 5. 파이프라인·기관 9곳·실행 명령·Docker (`feat/collector-pipeline`)
- **한 것**
  - 문서 코드를 그대로 넣었어요.
    - `sources/base.py`, `pipeline.py`, `sources/local/`(sh, apply_center(GH·부산), ih, dcco, dudc, umca, gbgn(경북·경남)), `sources/registry.py`, `__main__.py`
    - 테스트: `test_sources`, `test_pipeline`, `test_fixtures`, `test_storage_postgres`
  - `Dockerfile`, 루트 `.dockerignore`, compose의 `collector` 서비스(apps 프로필)
  - [collector README](../../services/collector/README.md): 명령, 확인 방법, 테스트, 새 기관 붙이기
- **문서와 다른 점**(설계 문서 두 곳도 고쳤어요)
  - Dockerfile `COPY ../../libs/...` → `COPY libs/...`: 빌드 컨텍스트가 저장소 루트라 문서 경로로는 빌드가 안 돼요.
  - uv 이미지 0.5.11 → **0.12.10**: `uv.lock`을 만든 버전과 맞췄어요(lock revision 3).
  - 실행 `uv run --no-dev …` → **가상환경 python을 바로 실행**: `uv run`은 컨테이너를 시작할 때마다 패키지를 다시 빌드·설치했어요("Building … Installed 2 packages").
  - compose collector: `minio` healthy를 기다리고, 8091은 `127.0.0.1`에만 열어요.
- **확인 결과**
  - `uv run pytest`: 56개 통과, 12개 건너뜀(저장 화면 9곳, 실제 DB 3개)
  - `test_storage_postgres`(`collector_test` DB): **3개 통과**. 전체 테이블 저장, 정정 확인 버전 2, `outbox.relay_once` 발행 2건, 실패 글, 보관 기한 정리
  - `docker build`: 성공. 컨테이너 안에서 `whoami` = collector, `hwp5html` 있음
  - `docker compose --profile apps run --rm collector … status`: DB 접속 성공(회차 없음)
  - `make up`(스케줄러)은 띄우지 않았어요. 새벽 3시 정정 확인 작업이 9곳 실제 사이트에 바로 요청할 수 있어서, 실제 사이트 확인은 6번에서 대전만 해요.
